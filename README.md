## What's in this repo

- `app.html` — page shell: all CSS + static markup, with three
  placeholders (`__ROSTER_JSON__`, `__NOTES_JSON__`, `__LOGOS_JSON__`)
  and a placeholder `<script>` tag that gets replaced with `app.js`.
- `app.js` — all client-side logic: roster browsing, role/PIN access
  (Admin / per-team / viewer), the live auction "Stage" (bidding &
  selling), the "Teams" and "Summary" views, the customizable
  export/download feature (CSV, an image+info HTML page, or a table
  PDF with embedded photos), and the Presenter mode.
- `data/roster_all.json` — the 144-player roster (all 4 semesters),
  each with name, USN, semester, gender, embedded photo (base64
  data URI), selected sports + self-ratings, and a photo-match
  quality flag. **Do not edit this file by hand** — it's the
  authoritative player data matched from the original registration
  forms + photo uploads.
- `data/data_notes.json` — data-quality notes (missing photos,
  orphan photos, malformed USNs) shown in the Roster tab.
- `data/team_logos.json` — base64-embedded logos for the 4 teams
  (Heyars, Zenith X, Hoysala, Phoenix).
- `jspdf.umd.min.js`, `jspdf.autotable.min.js` — the bundled
  open-source libraries (MIT licensed) that generate the PDF export
  entirely client-side, with no external network calls.
- `build.py` — merges `app.html` + `app.js` + the two PDF libraries +
  the three data files into one self-contained `dist/final_app.html`
  you can open directly in a browser or host anywhere.
- `dist/final_app.html` — a pre-built copy of the merged page (the
  same content that's live on the published Claude artifact), kept
  here as a safety backup so the data is never only in one place.
- `Robic_Quest_Cup_2026_Backup.xlsx` — a spreadsheet export of the
  roster, sales log, and team purses, as of when it was generated.

## Rebuilding the merged page

```bash
python3 build.py
```

This regenerates `dist/final_app.html` from the current `app.html` /
`app.js` / `data/*.json` — useful after you edit the app's UI or logic
without touching the underlying player data.

## Important: live auction data is NOT in this repo

The bidding/selling state (who's sold to which team, for how much)
lives in the **Claude artifact's own live database**, not in these
files — that's what lets every team member and the admin see the same
live auction from their own device in real time. This repo is the
*app itself* (the code + the static roster), so you can review it,
back it up, or redeploy it elsewhere. If you need a fresh snapshot of
the live sales data, ask Claude to export it again (it can pull the
current sales/teams state and add it to this repo or a new
spreadsheet).

## Running it locally

`dist/final_app.html` is fully self-contained (all CSS/JS/images
inline) — just open it in a browser. Note that outside of the
published Claude artifact, the live sync (`db`) and download
(`downloads`) features won't be available, since those depend on the
Claude artifact runtime; the roster browsing, presenter mode, and
static views work everywhere.
